## Context

The approved rendering contract remains Global / Pass (View optional) / Batch. The World bridge produces owned resource and entity commands; the editor host owns sequence allocation, submission, Busy retention and event consumption. Editor UI stays on the host thread.

## Decisions

- The editor binds its edit World, or the active Play World after `PlaySession::Tick`. The edit World does not run simulation. World extraction occurs before sealing the next host packet.
- A module-owned `WorldEditorState` resolves Actor selection to its registered component reflection. The Outliner contains only Actors in Transform parent/child preorder, retaining World order among siblings; an absent or external parent produces a root row. Selection and deletion use the real Actor UUID, without synthetic component IDs.
- The Inspector binds the selected Actor's components as sections of one existing ReflectedFormView, with Transform first. ReflectedForm supports grouped borrowed objects with distinct field-path namespaces and per-object defaults; scrolling, property widgets, notifications and undo remain shared. Unbinding clears every section before the World releases its storage. This does not introduce multi-Actor property merging or component add/remove actions.
- `COMPONENT_RUNTIME_INFO` supplies the complete concrete object address matching its registered type. Components without that opt-in remain uninspectable. This small Framework interface addition belongs to the editor change, not the bridge's lifecycle contract.
- Create/delete commands retain detached actors for undo. Document switches invalidate selection and history before old storage is released. Reflected property edits mark the document dirty; const getters must capture an owned previous value for undo.
- Built-in Cube and Plane persist reserved logical mesh UUIDs and regenerate CPU geometry through the same production asset source. They use the pass-owned default scene shader and generated Batch layout. No RHI object is persisted.
- Camera components drive the viewport; an editor camera at (0,0,5) is used when absent. The displayed viewport's actual arranged size drives offscreen resize and output revision.
- Scene projections are Y-up with depth in [0,1]. SceneRenderFeature converts them through the existing top-left logical output mapping before writing its generated Pass block; CPU frustum culling keeps the canonical projection. This applies equally before HDR tone mapping. New directional lights use degree-valued Euler angles, matching TransformComponent.
- Native inspection exposed descriptor exhaustion when a populated inspector and menu produced more than 128 UI draws. Vulkan and DX12 reuse immutable descriptor bindings within each raster pass, keyed by shader, exact uniform ranges/offsets, image views and sampler identities. Geometry and clipping remain per draw; caches never cross a pass or frame lease. The original budget remains unchanged and unique bindings still report exhaustion.
- The existing editor module configuration also supplies build-order dependencies through `sky_add_dependency` / `sky_set_dependency`, after all enabled targets exist. Building SandboxModule alone must refresh its configured runtime dependencies; runtime loading stays unchanged and no DLL link dependency is introduced. Disabled module targets remain excluded.
- Open menus own the shell surface's pointer routing until dismissed. Restricting the hit area to the first popup clips taller Create submenus even though their lower rows are painted. A shell-level regression covers the final child action and outside-click dismissal.

## Validation

Automated creation, reflected transform editing, undo/redo, delete/restore and save/reopen tests; Windows Vulkan dynamic/render-pass and DX12 image readback; native editor UI verification. Rebuild all component consumers after the virtual interface addition. Metal host migration remains separately tracked; Windows validation does not establish Metal device behavior.

Native World-open verification exposed a stale Aurora.ShaderCompiler DLL returning the previous ShaderBlockMember layout to a rebuilt SandboxModule. Debugger evidence located the access violation in reflection block copying. The build graph must include the module-to-module edges already declared in modules_editor.json, so a normal targeted module build cannot leave those runtime producers stale.
