## ADDED Requirements

### Requirement: Stage-scoped target specialization

Native metadata SHALL preserve stage, logical key, type, ID and value. IDs SHALL be reflected or generated by the target adapter, not supplied by Material/Pass values. Native values SHALL be applied to their own stage before execution; identical IDs in separate stages SHALL remain independent. Native selections SHALL preserve the published resource/ABI/I-O/workgroup-shape contract. Conservative native required-resource sets MAY exceed constant-folded sets and SHALL still be bound.

#### Scenario: Same numeric ID across stages
- **WHEN** VS and FS use ID 0 for distinct keys and values
- **THEN** both stages receive their independent values without collision

#### Scenario: Unsupported native shape change
- **WHEN** a native choice would change a shape the artifact/dispatch protocol cannot express
- **THEN** preparation uses an explicitly supported compile path or rejects the request

### Requirement: Stable logical parameter declarations

Complete logical parameter metadata SHALL be distinct from target-active resources and byte/native layouts. Material program families SHALL expose stable complete declarations and reject undiscoverable conditional declarations or type-changing keys. Target reflection SHALL remain inseparable from code and drive actual packing and binding.

#### Scenario: Optimized-away parameter
- **WHEN** a declared Material resource is inactive in a selected code artifact
- **THEN** it remains a known logical key and is absent only from the required target bindings

### Requirement: Complete selection and target execution identities

Caching SHALL distinguish complete normalized SelectionKey, per-stage StageCodeKey and device-scoped Executable/PSOKey. Complete selections SHALL include every effective typed V/P/S value. Stage code identity SHALL include source closure, stage/entry, target environment, schema/toolchain/lowering versions and code-affecting values. Native values MAY share code but SHALL distinguish executions. Full identities SHALL be checked on hash hits; input order and explicit defaults SHALL not create different selections.

#### Scenario: Native code sharing
- **WHEN** two selections differ only in a native value
- **THEN** eligible code is shared and executable identities differ

#### Scenario: Vertex layout changes
- **WHEN** stride changes without changing Shader features
- **THEN** code remains reusable while the vertex-input PSO remains correctly distinguished

### Requirement: Generated selection and target metadata products

Versioned products SHALL contain logical schemas, complete allowed selection records, stage code references, native mappings and target reflection. Shipping SHALL normalize and resolve without sources/compilers, reject absent selections even when generic code exists and validate complete environment/schema identity. The baseline v9 protocol SHALL be upgraded when these encodings change; incompatible records SHALL require recook.

#### Scenario: Uncooked native choice
- **WHEN** reusable code exists but the full requested choice is absent from the published catalog
- **THEN** runtime reports missing-selection rather than accepting unvalidated values

### Requirement: Common immutable preparation

All consumers SHALL resolve normalized immutable choices before graph build/recording. Ready, pending and error SHALL remain explicit, and code/interface/bindings SHALL publish as a coherent generation. Existing task/snapshot/module/GPU lifetimes SHALL be preserved. Material UUID or Tag alone SHALL NOT identify one reusable program across different V/P/S choices.

#### Scenario: Stale completion
- **WHEN** an older preparation completes after a newer request
- **THEN** it cannot replace the newer generation or relabel old bindings

## MODIFIED Requirements

### Requirement: bitmask key 与数据驱动 schema

ShaderVariantSchema SHALL describe typed logical keys, ownership, defaults and ranges independently of the legacy 128-bit ShaderVariantKey. Full selections SHALL use canonical typed key/value identities and support the schema's checked limits (1024 entries and 32768 logical bits). The retained bitmask helper SHALL reject values or layouts it cannot represent; it SHALL NOT limit production selection to 128 bits or truncate signed values.

#### Scenario: Complete selection exceeds the legacy key
- **WHEN** a valid typed selection needs more than 128 bits
- **THEN** normalization and artifact lookup preserve every value without requiring the legacy bitmask helper

#### Scenario: Legacy helper cannot represent the selection
- **WHEN** a caller explicitly uses ShaderVariantKey with an unsupported width
- **THEN** it reports failure instead of truncating the logical selection

### Requirement: 统一变体模型

Aurora SHALL normalize one typed key/value selection from Vertex, Pipeline and Shader-local inputs. Material, custom Batch, Fullscreen and Compute callers SHALL provide the Shader-local domain without requiring a Material object. Each logical key SHALL have one owner and a consistent type/range/default across stages. Unknown, duplicate, wrong-owner and invalid values SHALL fail explicitly. Omitted and explicit defaults SHALL normalize identically. Stage projection SHALL preserve only that stage's declared dependencies.

#### Scenario: Pass without Mesh
- **WHEN** fullscreen or compute supplies Pipeline and Shader-local inputs without Mesh input
- **THEN** it uses the same selector and validation as a scene request

#### Scenario: Duplicate or cross-domain input
- **WHEN** providers repeat a key or write a key owned by another domain
- **THEN** selection fails without order-dependent overriding

### Requirement: 机制由 shader 声明决定

Business inputs SHALL NOT select macro/native policy or native IDs. JSON companions SHALL retain logical key metadata and any explicit source-symbol association. The compiler SHALL derive target implementation and native mappings from validated shader declarations and target support. Supported macro or equivalent compile-time paths SHALL consume the selected values; native paths SHALL retain their stage/type/ID mapping. Unsupported conversion SHALL fail rather than becoming a uniform or using a default.

#### Scenario: One key across targets
- **WHEN** a shader key uses native specialization on a supported target and an explicitly supported compile-time path on another
- **THEN** the caller supplies the same semantic key/value and both execute that value

#### Scenario: Unrelated source symbol
- **WHEN** a source-symbol mapping is missing, ambiguous or semantically incompatible
- **THEN** compilation reports the key/stage/target rather than guessing from numeric IDs

### Requirement: 变体 key 组装

Production selection SHALL use canonical typed V/P/S keys. Mesh capabilities supply Vertex values; pipeline supplies Pipeline values; Material/custom Batch/fullscreen/compute supply Shader-local values. Owner, type, range, duplicate and cross-stage consistency SHALL be validated; explicit and omitted defaults SHALL normalize identically. Full selection SHALL NOT be limited by the retained 128-bit compatibility helper, and business values SHALL NOT choose macro/native IDs or policy.

#### Scenario: Cross-domain override
- **WHEN** Material tries to set a Vertex skinning key or Pipeline shadow key
- **THEN** selection fails without changing the previous prepared material

#### Scenario: Fullscreen without mesh
- **WHEN** fullscreen supplies P/S inputs and no Vertex inputs
- **THEN** it uses the same normalization contract and requires no dummy Mesh or Material
