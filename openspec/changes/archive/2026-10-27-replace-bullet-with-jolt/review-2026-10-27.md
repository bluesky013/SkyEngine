## 抽象与精简方案

保留用户已确认的 **adaptor + render**，无需创建 Jolt core。优先补足三个已有注册入口和一套编辑事务，而不是新增并行服务：

| 现有入口 | 应承担的职责 | 应删减的重复路径 |
| --- | --- | --- |
| WorldSubSystemRegistry | 配置描述、验证、带错误结果的构建、注册生命周期 | PhysicsBackendRegistry 的 WorldAttacher / AttachToWorld 在仓库中无生产调用者，核对外部 API 后移除；后者保留独立物理世界创建能力 |
| ComponentFactory | 类型安全创建、组件类型信息、必需子系统声明 | Actor 两条按反射 newFunc 强转的创建路径，宿主的 feature 依赖特判 |
| EditorActorCreation | 插件可注册的 Actor 预设创建入口 | SandboxModule 硬编码创建列表与 WorldEditorState enum switch |
| CommandService + ReflectedFormView | 配置和组件修改的原子提交、失败回退、Undo/Redo | 直接改 enabled 后 Rebuild/Save，以及为每种碰撞配置自绘表单 |
| PhysicsMeshProvider / 现有 Aurora CPU 解码 | 校验并提供消费方所需的碰撞几何 | 第二套 mesh schema、第二个作用相同的全局 geometry provider |

World 装配需要明确顺序：读取描述及未挂接 Actor → 验证配置/依赖 → 创建子系统 → 解析对象关系 → 挂接 Actor/组件 → 发布可运行 World；任一步失败回收候选对象。当前 [PhysicsSystem.cpp:26](D:/Code/Engine/SkyEngine/plugins/jolt/adaptor/src/PhysicsSystem.cpp:26) 遍历旧 Actor 并再次调用组件 OnAttach 的补丁虽能解决演示加载顺序，却要求每个 feature 重复补偿。应由 Framework 的统一装配阶段解决，避免将具体组件扫描扩散到各个子系统。

注册表还需明确同名注册和注销的所有权：当前 WorldSubSystemRegistry 允许覆盖且按名称删除；若支持替换，就必须防止旧注册者注销新注册者。最小策略是拒绝意外重复，并以注册句柄/owner 对应注销；不需要引入通用依赖注入容器。现有 DLL lease、唯一 metadata owner 和 Environment-backed Singleton 应保留，不能用幂等守卫掩盖重复反射。

推荐修复顺序：先处理 R2/R3/R4 的生命周期和错误边界，再处理 R1/R5/R6/R7/R11 的运行与资产正确性，随后用 R8/R9/R10 收敛配置/创建接口。新简单碰撞体、Mesh Collider 和制作工具应接到这些现有扩展点；本轮不夹带目录搬迁，也不将这些修复拆成额外 core 模块。

## 验收限制

本轮没有执行会触发悬空写入的 R2 或错误类型虚调用 R4；两项依据完整静态调用链判定。R1 为已核对生产者与消费者格式的代码缺陷，未新增 render bridge 集成用例。R3/R9/R10 为调用链审查；R5/R6/R7/R8/R11 有本轮运行证据。未重跑非 Windows 平台、Release 全套或性能基准。

原有后端测试和 DLL 生命周期测试覆盖仍有价值；它们不能代替上述 World / Editor / mesh bridge 集成验收。上述问题未修复前，本 change 不应标记为整体接入验收通过。

## 根因与修复结果（2026-10-27）

共同根因是迁移沿用了旧适配层的隐含假设，却没有把 World、反射、编辑历史、资产格式和物理帧的契约一起收紧。原测试主要覆盖独立后端 API；演示场景主要使用 primitive collider，没有走实际 cooked mesh → bridge → collider、配置历史 → World 构建、创建菜单 → 插件注册等路径。它们无法发现这些跨边界错误。

| 项目 | 具体根因 | 源头修复与新增证据 |
|---|---|---|
| R1 | 消费方把“位置紧密排列 + U32”当成资产格式，未读取生产者声明的 layout | 按 stride/POSITION offset/format/index type 转换并校验；MeshAssembler + writer + 二进制 header/bulk → Jolt 查询覆盖 U16/U32、交错顶点和坏索引 |
| R2 | WorldDesc/inline Any 的地址被当作永久身份，Undo 保存裸指针 | 配置命令按文档 lifetime、子系统名和类型重新定位；结构变动时重绑表单；覆盖 256 次 append、Undo/Redo、reload 失效 |
| R3 | Build 是 void/skip/assert；Load 先挂接 Actor，feature 再各自补扫；失败没有贯穿发布边界 | Load 准备未挂接 Actor，Build 统一验证/创建/挂接并返回错误；候选 World、组件半挂接和新子系统可回滚；缺失配置、工厂失败、缺失 mesh 后重试都有测试 |
| R4 | 把“类型已反射”错误等同于“类型是组件”，通过 void* 强转制造对象 | ComponentFactory 保存模板生成的 typed constructor；Actor 新增/反序列化共用它；普通反射数据 UUID 与未知 UUID 明确拒绝 |
| R5 | setter 采用先销毁再重建；反射 setter 和命令层又丢掉失败结果 | 候选先校验/cook，原 native body 更新，质量/形状保留 handle、速度、约束并修正 COM；bool setter 结果逐层返回，失败不进入 history；覆盖有效/无效编辑和事务 redo 回退 |
| R6 | 只有 physics→scene 写回，没有 scene→physics 输入，也没有明确读写阶段 | TransformEvent 传入 teleport/kinematic target；Actor Tick → subsystem Tick → PostTick，动态输出防反馈；覆盖静态移动、运动学目标保持及本帧动态插值 |
| R7 | 资产根只看到渲染组件，shape 树内 UUID 没有统一出口 | 刚体遍历 compound children 输出 typed assetRoots；空类型拒绝；真实 AssetTool 验证 collision-only 产品存在通过、删除后失败 |
| R8 | 把一次初始化的 Build 当作热更新接口，UI 行为与实际能力不一致 | 删除伪 Rebuild 路径；明确配置在下次 Play 生效，启用/禁用可撤销、不自动 Save；覆盖前后两次 Play 使用不同配置/启用状态 |
| R9 | 子系统依赖藏在宿主 animation 分支，没有组件声明 | ComponentFactory.requiredSubSystems 是依赖源；组件/Actor 创建和依赖启用一条可撤销命令；无 animation control 的测试组件同样生效 |
| R10 | 已有 creator 注册表只是旁路数据，真正菜单和构造仍是硬编码 | 复用注册表，稳定 id + callback + lease；菜单按 revision 更新，通用命令负责 attach/selection/history；真实 Sandbox action 测试注册、注销、过期入口和 undo 保活 |
| R11 | listeners 分发与无限保留的 polling queue 同时拥有事件，消费期限未定义 | listeners 收完整 host batch，polling 只保留当前 Tick/SingleStep，下一 host tick 退休；600 步不再累积历史，多监听者 Enter/Exit 顺序通过 |

保留 adaptor + render，删除未使用的 PhysicsBackendRegistry WorldAttacher 路径。World 注册仍为跨 DLL Singleton，拒绝同名覆盖，Jolt 仅注销自己成功注册的项；元数据继续由唯一 module definition 持有。没有新增并行 registry 或通用 DI 框架。

当前验证：Framework 207、EditorCore 184、EditorShell 144、Sandbox 创建/World 7、Jolt Debug 41 / Release 41、Recast 2、Terrain 2 均通过；Debug/Release 实际 DLL 两轮生命周期通过；打包配置 4、真实资产审计 4 通过。已有 SceneVerification 工程启动日志确认 editor shell、Jolt 两个模块、Vulkan swapchain 初始化和 renderer 正常停止。具体日志见 verification.md。

本轮没有重新做人工拖拽/Play 画面验收或跨平台验证；这些不冒充自动化测试结果。新 collider 资产、自动拟合/分解和专用制作 UI 仍属于独立 authoring 提案，尚未实现。静态凹形体原生未分配 motion state 时，转成动态体仍明确拒绝；不以销毁重建掩盖 handle 变化。提交和归档仍需独立确认。
