## Context

Framework owns foundational native platform implementations behind PlatformBase, NativeWindow and engine event types. Cocoa is the desktop backend, Android uses GameActivity buffers, and UIKit owns the iOS run loop. Existing backend directories and launcher templates are reused; no new platform plugin, editor dependency or RHI dependency is introduced.

## Goals / Non-Goals

**Goals:** align native window identity/events, client pixel input, app activity, timing and platform services; make the policy executable in tests; compile each native adapter against its actual SDK.

**Non-Goals:** GPU resource teardown/recreation, graphics capability probing, frame fences, shader compilation/asset conversion algorithms, first-class multi-touch, signed store distribution and Linux support. AssetTool bootstrap/configuration/result reporting is included in the package follow-up.

## Decisions

1. Add `PlatformBase::IsFrameActive` and `StopFrameLoop` through the existing Platform facade. Desktop remains active by default; mobile readiness is native app activity plus a live surface. Application still pumps events while suspended, skips ticks, and resets its per-instance FrameClock. Counter zero is a valid initial sample; invalid frequency or a counter discontinuity restarts sampling. A mobile launcher must honor initialization failure and application exit.
2. Keep the NativeWindow object and WindowID stable while the mobile native handle changes. Add a keyed OnSurfaceChanged event with the existing window as payload; consumers can inspect a null or replacement handle. This exposes the non-RHI lifecycle boundary without implementing renderer recovery in this change.
3. Use client framebuffer pixels for resize, pointer coordinates, relative movement and text-input rectangles. Cocoa/UIKit convert native points using the view's actual scale. Preserve wheel fractions as float; discrete wheel notches retain the existing 120-unit convention. Primary-touch mapping remains compatible with the existing mouse seam; secondary contacts do not generate duplicate button pairs.
4. Separate native input extraction from portable Android/iOS state and mapping policies. The real adapters call those policies, allowing regression tests on desktop without fake copies of the production behavior. Native SDK tests cover integration points and window lifetime where a GUI/runtime is available.
5. Reuse MultiFileSystem to select project/writable startup configuration before read-only bundle configuration. Android reads APK assets through its existing bundle filesystem and stages configs into assets. Both mobile backends keep work files in their app data directory, not their package. APK archives use a single checked buffered stream so compressed assets and mixed Get/Skip/LoadRaw reads have consistent positions. Mobile shell commands report unsupported instead of false success. The writable work filesystem is not replaced by a fallback bundle.
6. Implement the Unix/Android semaphore with the standard C++20 counting semaphore behind the existing opaque handle; macOS/iOS retain their existing Mach implementation. The Unix source is executable on the host without copying its production behavior. Semaphore objects are non-copyable. NamedThread joins its worker before destroying the semaphore used by queued signal closures. Application stops external callbacks, waits for asset workers and clears pending main-thread callbacks before unloading modules, then repeats the wait/clear before destroying asset managers. `ThreadDispatcher::Clear()` discards callbacks; it does not execute them.
7. Cocoa close notifications must tolerate a callback deleting the window. Notify the platform while the owner is valid, broadcast once, and do not access the owner afterwards. Native callbacks and display-link observers are detached before their C++ owners are destroyed.
8. Pin the Android launcher dependency to GameActivity 1.2.2 and link `game-activity::game-activity_static`. Its official archive contains GameActivity, GameTextInput and native app glue; remove all three inline source includes. The 1.1.0 source distribution has return-type errors under NDK 28, so suppressing diagnostics would retain broken upstream source. The [official integration guide](https://developer.android.com/games/agdk/game-activity/get-started) recommends the static library starting at 1.2.2. No general dependency upgrade or RHI dependency is added.
9. Native UIKit regression tests use a checked-in UIApplicationMain entry point and default to the iOS platform suites, because the broader desktop Framework tests assume host filesystem/process services. A standalone simulator recipe compiles the same production platform and test sources without requiring RHI or device signing.
10. Adopt the UIKit scene-based lifecycle for both the launcher and native test host. UIApplicationDelegate owns process initialization and termination; a UIWindowSceneDelegate connects the UI and forwards only its scene's activation, deactivation and disconnection. The public IOSSceneHost interface carries opaque native scene pointers, so the launcher depends on a Framework host contract rather than its concrete platform implementation. No UIApplication-wide activity notification may activate a disconnected or inactive scene.
11. Explicitly support one application scene (`UIApplicationSupportsMultipleScenes=false`). Bind UIWindow using `initWithWindowScene:` and derive geometry/scale from that scene and its view. Reject a second simultaneously connected scene and ignore callbacks from foreign/disconnected scenes. On disconnection, remove the UIKit representation and expose a null native handle while retaining the engine window ID and process-owned GameApplication. Reconnection recreates the native representation and restores frames only after activation. This prevents repeated reflection/module initialization and preserves explicit frame-loop stop requests.
12. Reuse one checked-in scene manifest for the CMake test App and standalone simulator recipe. Execute tests after UIKit delivers a real scene connection/activation, and keep native object/observer detachment in focused window helpers. Remove obsolete application activity observers and redundant native object aliases while preserving close/focus reentrancy and committed-text behavior.
13. Use one real generated game with only its game module requested by `modules_game.json` for package smoke tests. GameApplication still loads the actual renderer. Disable optional feature plugins in export presets, preserve those overrides on the first configure, and forward the same engine/cache/compiler arguments into Gradle's native build. Limit the smoke fixture's Ninja compile and link jobs with one shared pool.
14. Build iOS game modules statically, registering their tagged factories in the generated launcher. Dynamic iOS backend code must use an embedded framework with a bundle-relative load path. macOS modules use relative install names and are deployed inside the app. Default backend selection uses Metal on Apple, preserving explicit overrides and Vulkan defaults elsewhere, so packaged apps start without requiring a command line or a developer Vulkan SDK. Package resources follow the production platform bundle filesystem: iOS app root and macOS `Contents/MacOS`. Offline Content/Navigation builder targets are configured only on developing desktop hosts, keeping those standalone shared libraries out of mobile packages.
15. Collect an unsigned iOS archive as `Payload/<name>.app` and a macOS app ZIP while preserving executable modes and framework symlinks. Resource collection requires `signing=off`, because changing a signed bundle would invalidate its signature. Signed archive/export, provisioning and notarization need a separate distribution workflow. Report artifact structure, build success and actual runtime execution separately.
16. Retain owning filesystem pointers in AssetTool while handing roots to managers; a database retaining a child filesystem does not keep the original root alive. Load builder settings after module registration with project-first/engine-fallback configuration. Batch cook waits for actual completion results and returns failure when any product fails or produces no result; package propagates that exit status. This does not change conversion algorithms or fix the separate concurrent product-publication race.
17. Import Slang under its compiler SONAME and track matching-config runtime companions. For Android, generate a config/ABI manifest and feed companions through an AGP variant generated-jniLibs task after native build, without linking runtime-loaded plugins. Exclude linked imports and the byte-identical compatibility alias. For macOS, deploy visible imported runtime files on every invocation, preserving symlink chains. This models current global imports; it is not a general guarantee for arbitrary child-local imported targets or all special filename characters.

## Risks / Trade-offs

- [Shared event ABI] -> rebuild Framework, hosts and dependent modules together after the wheel type and event interface change.
- [Native GUI availability] -> retain executable portable tests and compile mobile/native test sources separately; record unavailable simulator/device validation accurately.
- [Mobile surface recovery needs consumers] -> expose and test OnSurfaceChanged and frame gating; RHI consumers remain a subsequent change.
- [Platform-only services] -> desktop implements shell/geometry/cursor services; mobile defaults explicitly fail or remain no-ops for unsupported desktop operations.
- [Existing iOS changes] -> keep their third-party, signing and device acceptance tasks independent; do not archive them automatically.
- [SDK availability] -> UIScene APIs used here are available from iOS 13. Validate against installed device/simulator SDKs and actual scene delivery; separately report that iOS 27 SDK/runtime validation is unavailable on the current Xcode installation. Do not equate source migration or an older simulator pass with an iOS 27 execution result.

The migration follows Apple's [UIKit scene lifecycle migration guide](https://developer.apple.com/documentation/uikit/transitioning-to-the-uikit-scene-based-life-cycle?changes=_4). Apple requires scene lifecycle adoption for apps built with the latest SDK beginning with iOS 27. Adopting scenes does not require enabling multiple simultaneous application windows. Scene disconnection is a UI resource boundary, not process termination.

## Migration Plan

Build and run CoreTest/FrameworkTest on the host, compile Core/Framework and launcher/test translation units against the Android/iOS SDKs, and run packaging config regression tests. Rebuild all shared-ABI consumers before running the editor or launcher. After verification and user confirmation, archive this change and commit its implementation, validation records and main-spec updates together.
