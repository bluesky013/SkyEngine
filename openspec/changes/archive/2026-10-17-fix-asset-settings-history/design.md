## Context

Materialized cook settings are disposable reflected UI models. AssetViewer::Reload replaces the Any after each committed edit, so commands cannot target those objects. The source manifest's target-specific sparse override is the persistent editing state; effective settings and baseline are regenerated by the asset builder.

## Decisions

### Session-owned history

AssetViewer owns a CommandService and injects it through ReflectedFormContext into cook forms and its generic registered DATA form. The service outlives child forms, whose teardown occurs explicitly in the viewer destructor body. Open/reopen/switch/close clear the session history; closing preserves already-persisted changes without cooking. SetCatalog clears history before replacing the borrowed service. Custom provider UI may have its own editing context; this change does not silently take ownership of it.

The scoped assetViewer Undo/Redo actions and enabled predicates use the viewer session. Viewer Undo/Redo immediately materialize pending settings; direct traversal of the injected service persists synchronously and requests pre-layout reload. The service remains toolkit/domain independent. T05's before-history hook cancels form previews before traversing this injected service as well as shared defaults.

### Domain commands own identity and snapshots

EditorAssetCatalog constructs AssetCookSettingsCommand from asset UUID, target name, reflected settings type UUID, and before/after BuildSettingsOverride maps. It borrows the catalog service, which must outlive its session, and retains no descriptor, field, TypeNode, widget, viewer, or settings Any. Property-edit construction first resolves a fresh effective object, finds the current top-level member by name/type, applies the requested value to that temporary copy, and derives the new sparse override with the builder.

Do and Undo use the same ApplyCookSettingsOverride operation. It rereads the current cook block, replaces only settings[target], removes empty canonical settings objects, persists through AssetDataBase::SetCookJson, advances the catalog revision, and notifies observers. Other targets and unrelated cook-block fields survive. A command is a target-state snapshot: normal sequential session undo restores that target's previous override, rather than attempting to merge concurrent external edits to the same target.

### Invalid identity and failures

Construction rejects unknown/read-only assets, unavailable targets, missing members, mismatched value types, and settings schema mismatches. Every execution resolves the current source, writable mount, target, and reflected schema identity again. Missing identity, removed target, or replaced schema produces no persistence and never accesses old UI/model memory. In the generic void Do/Undo contract, such stale operations still move the history cursor; the viewer clears local history when its next reload observes missing target/model/schema. This is deliberate safe invalidation, not a successful restoration claim.

Filesystem write failure also performs no stale model fallback. The generic CommandService interface has no command-result/error transaction protocol; detailed editor error presentation remains outside this repair. Schema identity detects a different reflected type UUID, while migration/versioning inside the same type remains the asset builder's responsibility. Module unload must still respect the lifetime of materialized models.

### Form seam and all edit paths

ReflectedForm accepts an optional EditCommandFactory taking a transient top-level PropertyDescriptor and new top-level Any. Its default uses MakeEditCommand as before. Domain factories must construct owned commands before returning and must not retain the descriptor or its target.

Nested edits continue to propagate their staged value to the top-level property before construction. Reset uses Edit. AddSequenceElement and RemoveSequenceElement stage a container value and call Edit, so they use the same factory and committed notification instead of bypassing the domain seam. Viewer OnEdited now reloads the current persisted state; persistence no longer depends on that callback.

### Reload and content invalidation

Command changes mark settings reload pending. SynchronizeLayout consumes it before form synchronization; catalog revisions also refresh externally persisted changes. Reload retains history for normal disposable-model replacement, but clears history for target-set/schema invalidation and missing assets. All old interactions cancel/detach before Any replacement. Target-set changes rebuild the owned forms and reset modal content/capture registrations. DATA-only viewers do not infer cook targets they do not display.

### Synchronous notification reentrancy

Catalog persistence notifies observers synchronously. ReflectedForm snapshots its command factory and changed callback before execution and checks a weak binding-generation signal afterwards, without retaining the generation or accessing the form after the command returns. Rebuild expires the generation; destruction expires it naturally. Forms are non-copyable so copying a token cannot make a dead form appear live. NotifyChanged also snapshots its callback before invocation.

An independent shared edit-counter state spans the committed Edit call. Its scope cleanup does not touch the form, so a core observer may destroy or rebind that form safely and its obsolete changed callback is suppressed. Viewer Open, Close, catalog replacement, and Reload defer lifecycle work while any owned form reports IsEditing. Nested SynchronizeLayout then only marks pending work. The next safe host layout after the widget event returns drains the queue; the edit scope destructor deliberately does not drain it because the widget/inline-event tail still uses the form. This also keeps old history isolated when the queued asset session finally opens.

CommandService Clear is a general history-generation boundary: commands executing across a synchronous clear must not be pushed back into the replacement session by Execute/Undo/Redo. The domain command contains no session logic. Arbitrary external deletion of a view while it is dispatching an event remains a host lifetime constraint; this repair coordinates the viewer's own lifecycle entry points rather than permitting uncoordinated deletion from any callback.

## Verification

Core regressions release heap-backed settings before Undo/Redo, verify target-specific maps and manifest contents, exercise scalar/reset/sequence factories, reject stale missing-target/schema commands, and destroy/rebind the editing form from a real catalog observer. Shell regressions execute actual viewer edits/reloads, check local/global history isolation, persisted undo and Save state, other target preservation, asset switching, close/reopen, missing asset cleanup, and scoped shell actions. Actual Generic inline-edit Enter events exercise observer-requested asset switch, target replacement with nested layout, and close; a synchronous Undo observer checks replacement-session counts. A combined domain-history/color-preview regression inspects the restored preview from inside persistence notification before Reload can mask incorrect ordering, then verifies persisted maps, UI values, cursor counts, late Escape/release, and Save after Undo. ASan must cover both the disposable model path and the real host path. No native GPU behavior is changed by this task.
