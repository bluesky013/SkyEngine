## ADDED Requirements

### Requirement: Aurora vegetation feature processor

The aurora render layer SHALL provide a vegetation feature processor that participates in the aurora scene lifecycle, pulls vegetation cell data from the core sub-system each frame, and owns all vegetation GPU resources.

#### Scenario: Register vegetation feature

- **WHEN** the aurora vegetation render module is initialized
- **THEN** a vegetation feature processor SHALL be available to aurora scenes without the core referencing any render type

#### Scenario: Consume core cell data

- **WHEN** the feature processor updates
- **THEN** it SHALL obtain cell bounds, biome/palette parameters, density data, and a surface sampling handle from the core sub-system

### Requirement: Render adaptor seam

The core SHALL define a render adaptor/factory seam and hand over plain data, and the aurora module SHALL register an adaptor implementation, so the core never includes or links aurora/render/RHI types and the renderer is replaceable.

#### Scenario: Core has no renderer dependency

- **WHEN** the core vegetation module is compiled
- **THEN** it SHALL NOT include or link aurora, render, or RHI types

#### Scenario: Register the aurora adaptor

- **WHEN** the aurora vegetation plugin is initialized
- **THEN** it SHALL register its render adaptor with the core factory seam

#### Scenario: Alternative adaptor

- **WHEN** a different render adaptor implementation is registered
- **THEN** the core SHALL drive it through the same seam without code changes

### Requirement: GPU-driven population

The render layer SHALL generate vegetation instances on the GPU from the density field, consuming plain data handed over by the core, and SHALL NOT require the core to allocate GPU resources.

#### Scenario: Populate on the GPU

- **WHEN** a cell is rendered
- **THEN** its instances SHALL be generated by a GPU population stage from the cell's density and biome parameters

#### Scenario: Core stays GPU-free

- **WHEN** the core vegetation module is linked without the render layer
- **THEN** it SHALL build and run without any GPU resource

### Requirement: Instanced and billboard render tiers

The render layer SHALL render vegetation using instanced meshes for near cells and merged/billboard patches for far cells, with density LOD fade between tiers so transitions are not abrupt.

#### Scenario: Near instanced draws

- **WHEN** a cell is within the near tier distance
- **THEN** its vegetation SHALL be drawn as instanced meshes

#### Scenario: Far merged patches

- **WHEN** a cell is beyond the far tier distance
- **THEN** its vegetation SHALL be drawn as merged/billboard patches with reduced density

#### Scenario: Fade between tiers

- **WHEN** a cell crosses a tier boundary
- **THEN** the transition SHALL be blended rather than a hard swap

### Requirement: Wind deformation

The render layer SHALL apply a global wind field (direction, strength, noise) to per-instance vegetation deformation driven by the core's wind parameters.

#### Scenario: Wind animates vegetation

- **WHEN** the wind parameters are non-zero
- **THEN** vegetation instances SHALL deform according to the wind field

### Requirement: Character interaction

The render layer SHALL bend vegetation near interacting actors using an interaction buffer or texture written with actor position/radius/strength, with a bounded number of interacting actors.

#### Scenario: Vegetation reacts to actors

- **WHEN** an interacting actor moves through a vegetation cell
- **THEN** nearby vegetation SHALL be displaced away from the actor

### Requirement: Foliage-lit dedicated pass

The render layer SHALL render vegetation in a dedicated pass with foliage lighting (blade light attenuation and translucency) and shadow participation, using vegetation techniques/materials.

#### Scenario: Dedicated vegetation pass

- **WHEN** a scene with vegetation is rendered
- **THEN** vegetation SHALL be drawn in its dedicated pass with the foliage lighting model, not as opaque geometry under the standard material

### Requirement: Render-agnostic core handoff

The core vegetation module SHALL NOT reference the aurora render layer or any GPU type; the handoff from core to render SHALL be plain data and identifiers only, delivered through the render adaptor seam.

#### Scenario: Core has no aurora dependency

- **WHEN** the core vegetation module is linked without the aurora render layer
- **THEN** it SHALL compile and link successfully

### Requirement: Vegetation culling

The render layer SHALL cull vegetation at cell and instance granularity: cells SHALL be frustum- and distance-culled using conservative bounds inflated by the maximum vegetation height, and instances SHALL be frustum-culled on the GPU during population with per-cell indirect draw arguments, so fully culled cells emit no draw.

#### Scenario: Frustum-cull cells

- **WHEN** a loaded cell's inflated bounds are outside the camera frustum
- **THEN** the render layer SHALL NOT submit that cell for drawing while keeping it resident

#### Scenario: GPU instance culling

- **WHEN** a cell is drawn
- **THEN** individual instances outside the frustum SHALL be culled on the GPU and excluded from the instance count

#### Scenario: Empty cells emit no draw

- **WHEN** a cell has no instances after culling
- **THEN** its indirect draw SHALL be skipped (zero instances)

#### Scenario: Culling does not affect residency or query

- **WHEN** vegetation is culled for rendering
- **THEN** the core cell residency and presence/density queries SHALL be unaffected
